# SupportPilot 使用说明书

> **本文供作者熟悉项目；对外 / GitHub / Upwork 请看英文 [`docs/USER_GUIDE.md`](../USER_GUIDE.md) 与根目录 [`README.md`](../../README.md)。**

本文结构与英文指南一致，便于对照学习。数据与上游均为 **mock**；开发过程使用 **AI 辅助**；**非生产产品**。不要编造用户量、营收、可用性 SLA 或评测通过率。

---

## 1. 项目是什么 / 不是什么

### 是

- **LangGraph + FastAPI** 客服 Agent，具备：
  - 基于政策 Markdown 的 **RAG**（带引用）
  - **工具调用**（订单、物流、退货、预约、CRM、转人工）
  - **Next.js** 聊天 UI（SSE 流式）与管理后台（知识库、Trace、工单、Mock 故障率）
- 可用 **Docker Compose**，或本地 backend + frontend 对接 Postgres/pgvector
- 通过环境变量对接任意 **OpenAI 兼容** LLM
- 无付费 API Key 也可跑测试（单测用 Fake LLM；有效 embedding API Key 未设置时用 Fake embeddings）

### 不是

- 真实 Shopify / 支付 / 多租户 SaaS
- 具备生产级鉴权与密钥管理的上线系统
- 可随意宣称的业务或评测指标来源（`evals/report.md` 在真实跑评测前保持占位）

## 3. 环境变量

```bash
cp .env.example .env
```

来自 [`.env.example`](../../.env.example)：

| 变量 | 作用 | 示例 / 默认 |
|------|------|-------------|
| `LLM_BASE_URL` | OpenAI 兼容对话 API 根地址 | `https://api.openai.com/v1` |
| `LLM_API_KEY` | 对话 API Key（直播 Chat / 评测需要） | *(空)* |
| `LLM_MODEL` | 对话模型 | `gpt-4o-mini` |
| `EMBEDDING_BASE_URL` | 可选独立 Embedding API 根地址；空则复用 `LLM_BASE_URL` | *(空)* |
| `EMBEDDING_API_KEY` | 可选独立 Embedding API Key；空则复用 `LLM_API_KEY`。解析后仍为空 → Fake embeddings | *(空)* |
| `EMBEDDING_MODEL` | Embedding 模型 | `text-embedding-3-small` |
| `EMBEDDING_DIM` | 向量维度（需与模型/库列一致） | `1536` |
| `DATABASE_URL` | 异步 SQLAlchemy URL | Compose 内：`...@db:5432/...`；宿主机迁移/种子：`...@127.0.0.1:5432/...` |
| `MAX_STEPS` | Agent 最大步数，超限转人工 | `8` |
| `MAX_TOOL_ERRORS` | 工具错误次数上限 | `3` |
| `REQUEST_TIMEOUT_S` | 请求超时（秒） | `60` |
| `ADMIN_PASSWORD` | 后台 `X-Admin-Password` | `change-me` |
| `MOCK_LATENCY_MS` | Mock API 人为延迟 | `0` |
| `MOCK_FAILURE_RATE` | Mock 失败概率 `0.0`–`1.0` | `0.0` |
| `MOCK_BASE_URL` | 工具访问 Mock 的基址 | `http://127.0.0.1:8000` |
| `WEBHOOK_URL` | 转人工/预约可选回调 | *(空)* |
| `NEXT_PUBLIC_API_URL` | 浏览器访问后端 | `http://127.0.0.1:8000` |
| `NEXT_PUBLIC_ADMIN_PASSWORD` | 前端管理门禁（同 Header） | `change-me` |

代码中还有 `USE_FAKE_EMBEDDINGS`、`RAG_DISTANCE_THRESHOLD`、CORS 等（`app.config.Settings`）；上表覆盖 `.env.example` 面向操作者的项。管理后台 **Settings** 会展示解析后的 Embedding Base URL，以及 embedding Key 是否已配置（仅布尔值，从不回传明文 Key）。

### LLM 提供商示例（OpenAI 兼容）

```bash
# OpenAI
LLM_BASE_URL=https://api.openai.com/v1
LLM_API_KEY=sk-...
LLM_MODEL=gpt-4o-mini
EMBEDDING_MODEL=text-embedding-3-small
EMBEDDING_DIM=1536

# 通义千问（DashScope 兼容模式）
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_API_KEY=sk-...
LLM_MODEL=qwen-plus
# Embedding 请选账号支持的模型，并保证 EMBEDDING_DIM 一致

# Gemini OpenAI 兼容端点
LLM_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai/
LLM_API_KEY=...
LLM_MODEL=gemini-2.0-flash
```

后端用 `LLM_*` 构建 `ChatOpenAI`（`app.agent.llm`）。模型需支持 **tool / function calling**。

## 4. 两种运行方式

### A. Docker Compose（推荐演示）

```bash
cp .env.example .env
# 可选真实 LLM：
# LLM_API_KEY=...   LLM_BASE_URL=...   LLM_MODEL=...

docker compose up --build
```

再在宿主机对已发布的 Postgres（`localhost:5432`）执行迁移与种子：

```bash
cd backend
export DATABASE_URL=postgresql+asyncpg://supportpilot:supportpilot@127.0.0.1:5432/supportpilot
uv sync --all-groups
uv run alembic upgrade head
uv run python -m scripts.seed   # 幂等，可重复执行
```

Compose 服务：`db`、`backend`(8000)、`frontend`(3000)。容器内 `DATABASE_URL` 指向主机名 `db`。

### B. 本地 backend + frontend（数据库单独起）

1. 先起带 pgvector 的 Postgres（可只起 Compose 的 `db`：`docker compose up db`）。
2. 后端：

```bash
cd backend
export DATABASE_URL=postgresql+asyncpg://supportpilot:supportpilot@127.0.0.1:5432/supportpilot
uv sync --all-groups
uv run alembic upgrade head
uv run python -m scripts.seed
uv run uvicorn app.main:app --reload --port 8000
```

3. 前端（Node 版本见 `.nvmrc`）：

```bash
cd frontend
npm ci
npm run dev
```

确认 `NEXT_PUBLIC_API_URL` 与 `MOCK_BASE_URL` 能从工具层访问到后端。

## 6. 使用 Chat UI

打开 http://127.0.0.1:3000/chat。

**要做像样的直播演示，请配置 `LLM_API_KEY`（及匹配的 `LLM_BASE_URL` / `LLM_MODEL`）。** 可选单独设置 `EMBEDDING_BASE_URL` / `EMBEDDING_API_KEY`；留空则复用 `LLM_*`。解析后的 embedding Key 仍为空时，embedding 走确定性 Fake（适合 CI/种子）；Chat 仍会建真实 `ChatOpenAI` 客户端，**不会**自动换成单测里的 `ScriptedFakeChatModel`。

### 示例问题（与 UI 快捷按钮一致）

来自 `frontend/app/chat/page.tsx`：

1. `What is your return policy?` — RAG；应有 **引用**（文档名 + 片段）。
2. `Where is order A1001? email jane@example.com` — `get_order`；校验通过后可出订单卡片。
3. 同一订单换错误邮箱 — **订单号 + 邮箱双校验**，不匹配不泄露。
4. `I want to return order A1003, email sam@example.com` — 窗口内退货 → RMA。种子订单 **A1005** 等可演示超期拒绝。
5. `Book a call-back for jane@example.com tomorrow` — 查空档并预约。
6. `I need to talk to a human` — 转人工，返回工单号，会话 `handed_off`。

流式：SSE 事件 `token`、`tool_end`、`citation`、`final`、`error`。

### 常用种子订单

| 订单 | 邮箱 | 演示用途 |
|------|------|----------|
| A1001 | jane@example.com | 在途查询 |
| A1003 | sam@example.com | 合法退货 / RMA |
| A1005 | casey@example.com | 超退货窗口 |

完整数据：`backend/scripts/seed.py`、`backend/seed_kb/*.md`。

## 7. 管理后台

门禁密码与 `ADMIN_PASSWORD` / `NEXT_PUBLIC_ADMIN_PASSWORD` 一致（默认 `change-me`），请求头 `X-Admin-Password`。

| 区域 | 做什么 |
|------|--------|
| **Knowledge** | 上传 Markdown/PDF 或 URL；看切分/向量化状态；删除文档 |
| **Conversations** | 会话列表；点进查看 **Trace**（节点、工具入参/出参、耗时、重试、错误） |
| **Tickets** | 转人工工单；改状态 `open` / `in_progress` / `resolved` |
| **Settings** | 查看模型与护栏（含解析后的 **Embedding Base URL** 与 **embedding Key 是否已配置**）；调节 **Mock failure rate / latency**，演示重试→转人工 |

对应 API 见 `/docs`：`/api/kb/*`、`/api/conversations/*`、`/api/tickets`、`/api/admin/*`。

## 8. 工具列表与护栏

### 工具

注册于 `app.tools.registry`（schema 与 SPEC §7 对齐）：

| 工具 | 作用 |
|------|------|
| `search_knowledge_base` | 回答政策前先检索 |
| `get_order` | 查订单；**必须** order_id + email |
| `track_shipment` | 物流轨迹 |
| `create_return_request` | 创建 RMA |
| `check_availability` | 回电空档 |
| `book_appointment` | 预约 |
| `upsert_crm_contact` | 写入 Mock CRM |
| `handoff_to_human` | 建工单并转人工 |

Mock 上游：`/mock/orders/...`、`/mock/shipping/...`、`/mock/calendar/...`、`/mock/crm/contacts`、`/mock/returns`。

### 护栏

| 护栏 | 行为 |
|------|------|
| 工具超时 / HTTP 5xx | tenacity 退避，**最多 3 次**；每次记入 Trace |
| 4xx / 业务错误 | **不重试**；结构化错误回传 LLM |
| `MAX_STEPS`（默认 8） | → 转人工（`low_confidence`） |
| `MAX_TOOL_ERRORS`（默认 3） | → 转人工（`tool_failure`） |
| 结构化输出失败 | 明文兜底，低 confidence |
| 订单类工具 | 订单号+邮箱双匹配，否则 404 |
| `WEBHOOK_URL` | 转人工/预约可选回调，最多重试 3 次，不阻塞回复 |

图流程：`guard → agent ⇄ tools → finalize | handoff`。

### 质量检查 / 单测（无需 API Key）

```bash
uv run ruff check .
uv run mypy app
uv run pytest
```


## 11. 架构

![SupportPilot 架构图：Next.js → FastAPI → LangGraph（guard / agent / tools / finalize / handoff）→ pgvector RAG 与 Mock API](../architecture.png)

> 上图与英文指南共用同一份 PNG/SVG，**不重复存放**。源文件：[architecture.mmd](../architecture.mmd) · [architecture.svg](../architecture.svg)

**文字说明：** Next.js 通过 REST/SSE 调用 FastAPI。对话进入 LangGraph：`guard` 做输入与安全检查；`agent` 调用带工具绑定的 OpenAI 兼容 LLM；`tools` 做参数校验、超时与重试，并访问 **pgvector RAG** 与 **Mock 店铺 API**；正常结束走 `finalize`（结构化 `AgentReply`）；步数/错误上限或显式转人工工具走 `handoff`（工单 + 可选 `WEBHOOK_URL`）。会话、Trace、知识库分块、工单存在 **PostgreSQL + pgvector**。

根目录 README 中亦有同结构的 Mermaid 图。

## 12. 已知限制

- 仅有 Mock 店铺 / 日历 / CRM — 无真实 Shopify、支付、多租户
- 管理端鉴权仅为演示用共享密码 Header
- 无解析后的 embedding API Key 时 embedding 为 Fake；直播 Chat 需要真实支持 tool calling 的模型（`LLM_API_KEY`）
- SPEC 中可选的 n8n 示例工作流（M11）未包含
- 评测数字只能来自真实 `evals.run_evals`，作品集中不要编造通过率
